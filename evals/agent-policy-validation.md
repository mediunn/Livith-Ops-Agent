## 이번에 막은 실패

- 기본 요청에 현재 지표·직전 지표·서비스 로그를 필수로 저장합니다. 미완료 상태에서는
  `finish`가 생성 스키마에서 제외되고 사후 검사·그래프·보고서도 조기 완료를 거부합니다.
- `--no-compare-previous`는 직전 구간 비교를 끕니다. 요청과 SQLite에 저장하고 재개 시
  유지합니다. 자연어 문장에서 비교 요구를 추출하는 기능은 아닙니다.
- 새 모델 출력은 `action`·`claim_ids`만 허용합니다. ‘정상’ 같은 추가 문장을 출력하면
  `schema_error`로 거부하고 한 번 수정합니다. 실패 원문은 진단 receipt에 보존합니다.
- `required_checks`로 조회 이행과 데이터 확보를 구분합니다. `no_data`·`invalid_data`도
  조회 완료로 계산하지만 정상 근거로 삼지 않습니다. 실패·예산 소진은 `incomplete`입니다.

보고서의 `narrative_source`는 `code_generated`, `health_assessment`는 `not_evaluated`,
`model_assessment`는 null, `hypotheses`는 빈 배열입니다. 분류는 모델의 판단이 아닌
관측 정책이며 `assessment_source=observation_policy`로 표시합니다.

## 외부 호출 없는 검사

pytest **238개**, Ruff, 형식 및 diff 검사를 통과했습니다. 이전 v3 회귀 검사를 보존하면서
새 v4 계약에 대한 다음 검사를 추가했습니다.

- 다른 구간·도구·실패 결과를 필수 조회 완료로 인정하지 않는지 확인.
- 데이터 없음·잘못된 수치를 정상으로 바꾸지 않는지, 예산 부족을 완료로 처리하지 않는지 확인.
- 자유 문장 주입 거부·수정·실패 원문 보존, 코드 설명과 원본 모델 응답 분리.

- v2·v3 체크포인트는 자동 재개하지 않는지 확인. 과거 결과 파일은 유지합니다.

## 해석과 남은 한계

이 결과는 모델의 자유 문장 추론 능력이 좋아졌다는 뜻이 아닙니다. 출력 역할을 줄이고
필수 조회와 설명을 코드가 보장하도록 변경한 결과입니다. 이전 버전과 계약·분류 주체가
달라 단순 정확도 비교로 해석하면 안 됩니다. 예전 결과는 그대로 보존했습니다.

- 집계 요약에서 원인을 추론하는 기능은 제거했습니다. 원인 분석을 다시 지원하려면
  로그·코드·배포 등 추가 근거와 별도의 검증 계약이 필요합니다.
- 증상 문장에서 필수 조사 항목을 추출하지 않습니다. 명시적 비교 옵션을 따릅니다.
- 선택적 `warning_logs`도 모든 평가에서 실행했습니다. 조회 효율이 개선됐다는 근거는 없으며,
  필요한 경우에만 추가 조회하도록 하는 평가가 남아 있습니다.
- 정책 문장과 조회·선택의 적절성은 계속 검토 대상입니다. 작은 반복 사례 결과이며
  독립 평가 세트가 아닙니다. `semantic_review`는 `pending`으로 유지합니다.
- 상태 v2·v3는 새 계약으로 자동 변환하거나 재개하지 않습니다. 새 조사를 시작해야 합니다.
