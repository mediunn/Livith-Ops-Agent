# HTTP 조사 루프 검증

검증일: 2026-09-28 (Asia/Seoul). 계약 `http-agent-v1`, 프롬프트 `http_agent_v1`.
프롬프트 SHA256: `4d514fa0f654e3cd02580b9ae35527af1e2e657b955ade6bc44d4a9b7b70515f`.

## 검사 범위

초기 요청률·평균 지연은 코드가 조회하고, 이후 endpoint·metric·window·종료를 planner가 선택한다.
endpoint는 초기 관측에서 얻고, 조회는 고정 템플릿을 통해 실행한다. 선택 이력과 인용한 가설이
보고서에 남는다. 추가 조회는 필수가 아니며 잘못된 선택은 실제 평가 실패로 남는다.

자동 테스트는 후보·직접 실행 경계·범위 이탈·중복·존재하지 않는 근거 ID·출력 수정 1회·
시간 및 호출 제한·SQLite 재개·중단 시간 제외·MCP 세션 소유 작업·CLI 검증을 다룬다.
주입한 planner로 후속 근거를 받아 같은 가설을 기각하는 흐름도 확인했다.
이 테스트는 실제 LLM이 올바른 판단을 한다는 증거가 아니다.

## 실제 3B 모델과 규칙 비교

최종 스키마 검사 실행 ID: `5abdc8366a4c45f5aefa2f62879a60fe`.
원본은 `artifacts/evaluations/http-agent/<ID>/`에 저장했다. 모델 `qwen2.5:3b`, temperature 0,
입력 컨텍스트 16,384, 출력 상한 1,024, 조회 예산 6회, 실행 시간 180초.
세 비교 사례에는 증상과 관계없는 25,000ms 내부 대기 엔드포인트를 함께 넣었다.

| 사례 | 규칙: 필요한 직전 조회 | 3B: 필요한 직전 조회 | 3B 종료 |
|---|---|---|---|
| checkout 평균 지연 100 → 800ms | 실패 | 실패 | decision_error |
| orders 요청률 8 → 0 req/s | 실패 | 실패 | planner_finished |
| checkout 지연 증가 의심, 실제 800 → 800ms | 실패 | 실패 | planner_finished |
| 데이터 없음 | 후속 조회·LLM 호출 없음 | 후속 조회·LLM 호출 없음 | no_candidates |

3B 모델은 세 비교 사례에서 총 9회 호출됐다(수정 재시도 3회 포함). 실제 입력 토큰 합계
22,909, 출력 2,631이다. 모두 같은 조회를 중복 실행하지 않았고 조회 예산을 지켰다.
하지만 필요한 직전 비교는 0/3, 예상 가설 상태와 양쪽 구간 인용의 조합도 0/3이었다.
데이터 없는 사례는 코드가 처리하므로 모델 판단의 성공으로 세지 않는다.

모델은 checkout 지연 조사에서 요청률·뒤 절반을 선택했고, 이미 실행한 조건을 다시 골라
검증에서 종료됐다. orders 사례도 뒤 절반을 본 뒤 끝냈다. 증가 의심 반박 사례에서는
직전 구간 없이 증가를 지지한다고 썼다. 따라서 `planner_finished`는 조사 루프 종료이며
판단 정확성이나 장애 판정의 보증이 아니다. 모델의 가설 의미 검토는 자동 점수와 별도다.

규칙 기준선은 가장 높은 지연의 `/internal/poll`만 비교한다. 이 데이터셋에서는 세 번 모두
증상 대상을 놓치므로 약한 기준선이다. 현재 결과로 LLM의 우월성을 주장할 수 없다.
이후 [동일 예산의 3B·14B 비교](http-model-comparison.md)를 추가했다.
증상 대상을 반영하는 더 강한 규칙 기준선은 아직 실행하지 않았다.

첫 실행 `97fcbd07dfb94a2d8b3d5886806e34ff`에서는 query의 인자 누락도 발생했다.
이에 JSON 스키마에서 nullable 조회 필드를 필수 키로 지정했다. 선택 가능한 endpoint·metric·window는
유지했다. 위 표는 그 변경 후 결과다. 실패 원문도 삭제하지 않았다.

## 실제 Grafana 검증

규칙 planner로 추천 API GET `/api/v7/recommendation//concerts`를 조사했다.
현재 구간은 `2026-09-26T12:00:00Z`~`2026-09-27T12:00:00Z`, 직전은 같은 길이의 이전 구간이다.
실행 ID는 `e2144e67a7d6474e9d6dfe47672cbc1f`이며 `artifacts/http-agent/<ID>/report.json`에 저장했다.

첫 조회 후 `--step`과 같은 방식으로 중단하고 SQLite에서 재개했다. 최종 결과는 `completed`,
`planner_finished`, 도구 4회, 모델 0회이며 네 조회 모두 `data_available`이었다.
캐시된 mcp-grafana v1.6.0을 offline 옵션으로 사용했다. 실행·재개 각각 한 세션을 열고 정상 종료했다.
초기 실측에서 발견한 AnyIO 세션 진입·종료 작업 불일치는 세션 생성을 그래프 호출 바깥으로 옮겨 수정했다.

이는 실제 연결·파싱·조건별 조회·재개·세션 종료 검증이다. 실제 운영 데이터에서 LLM이 적절한
조사나 원인 분석을 했다는 검증은 아니다.
