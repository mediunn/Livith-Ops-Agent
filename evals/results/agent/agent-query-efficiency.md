# 추가 로그 조회 효율 검증

[평가 안내](../../README.md) · [이전 필수 조회 검증](agent-policy-validation.md)

2026-09-27, `ops_agent_v8` / `investigation-policy-v2` / `qwen2.5:3b`를 사용했습니다.
상태·보고서 버전은 v4를 유지합니다.

## 변경한 판단

현재 지표·직전 지표·서비스 로그를 먼저 확인합니다. 같은 범위의 서비스 로그가 성공적으로
반환되고 100건 미만이며 서버 잘림·한도 도달·잘림 가능성 플래그가 모두 명시적으로 false이면
부분집합인 `warning_logs` 조회를 제외합니다. 반환 상태·건수·한도·범위 메타데이터가
일치해야 합니다. 잘림, 100건 도달, 완전성 정보 누락·불일치이면 추가 조회를 허용합니다.

경고 레벨이 없다는 이유로 조회를 생략하지 않습니다. 일반 로그가 잘렸다면 한도 밖의 경고를
문자열 조회로 찾을 수 있습니다. 반대로 잘리지 않은 로그에 이미 경고가 있어도 재조회는
생략하며 기존 경고 관측을 보존합니다. 문자열 매칭을 경고 레벨로 취급하지 않습니다.

`warning_log_followup`에 적격 여부·이유·근거 ID·실제 조회 여부를 남깁니다. 모델 입력,
스키마, 사후 검사와 실제 호출 직전 검사에 같은 정책을 적용합니다. 이전 v4 실행의 저장된
선택이 현재 정책에 어긋나면 재개 시 `optional_query_blocked`로 중단하고 기록을 보존합니다.

## 검증 범위

합성 데이터는 기존 Prometheus/Loki 파서로 처리하고 실제 모델·planner·LangGraph·SQLite·예산·보고서를
실행합니다. 기대 결과는 모델에 주지 않습니다. 별도로 실제 Grafana 조회를 실행합니다.
단위·회귀 테스트 266개, Ruff 검사·포맷·diff 공백 검사가 통과했습니다. 경계 99/100건,
메타데이터 누락·불일치, 필수 조회 우선, 차단된 선택 및 SQLite 재개 시 호출 차단을 포함합니다.

이 검증은 고정 사례의 조회 선택과 관측 보존에 관한 것입니다. 서비스 전체 건강·원인·모델의
일반적인 추론 품질을 검증하지 않습니다. 서버 메타데이터를 신뢰하며 이후 지연 수집된 로그는
포함하지 않습니다. 추가 조회는 필수가 아니므로 예산·모델 선택에 따라 실행되지 않을 수 있습니다.
`semantic_review`는 별도 검토 전까지 `pending`으로 유지합니다.

## 합성 관측 + 실제 모델 결과

7개 사례를 두 번씩 실행한 14건 모두 10개 자동 조건을 통과했습니다. 수정 호출은 없었습니다.

| 사례 | 추가 경고 조회 | 도구 / 모델 호출 (각 반복) | 결과 |
|---|---|---|---|
| `zero_no_logs` | 생략 | 3 / 3 | 2/2 통과 |
| `rate_increase` | 생략 | 3 / 3 | 2/2 통과 |
| `warning_present` | 수행 | 4 / 4 | 2/2 통과 |

| `unknown_log_completeness` | 수행 | 4 / 4 | 2/2 통과 |

이전 v7 네 사례는 매번 도구·모델 각 4회였습니다. 동일한 기존 사례 중 `zero_no_logs`,
`rate_increase`, `regex_info_only`는 각각 3회로 줄었고 `warning_present`는 4회를 유지했습니다.
신규 `complete_warning_logs`도 3회이며 경고 관측을 보존했습니다.
이 차이는 정책과 프롬프트를 함께 바꾼 결과입니다. 실행 시간은 장비 상태에 영향을 받으므로
지연 시간 개선의 벤치마크로 해석하지 않습니다.

합성 suite: `agent-6d7373b30d8f4f71998412a3ee8384d7`.

Japan Langfuse 서버에서 14개 trace, 110개 observation, 140개 자동 점수를 읽어
부모 연결·모델 입력/출력·검증 결과·최종 보고서를 로컬 기록과 대조했습니다.
