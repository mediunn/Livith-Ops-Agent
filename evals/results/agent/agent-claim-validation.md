# Agent 관측 주장 정책 검증

[평가 안내](../../README.md) · [기존 참조 검사 결과](agent-reference-validation.md)

2026-09-27에 `ops_agent_v4`와 `observation-claims-v1`을 확인했습니다.
모델이 사실 문장·값을 작성하는 대신, 코드가 계산한 관측 목록에서 `claim_ids`를 선택합니다.
지원 범위는 반환 로그에 기록된 경고·오류 레벨과 동일 API의 구간 마지막 요청률 증가입니다.
원인 가설과 자유 문장 전체의 사실성을 검증하는 기능은 아닙니다.

## 외부 호출 없는 검사

전체 pytest 203개가 통과했습니다. 새 정책 관련 양성·음성 검사에는 다음이 포함됩니다.

- 경고·오류 레벨 집계와 요청률 증가를 허용하고, 0→0·감소는 증가로 표시하지 않습니다.
- 문자열 매칭만 있는 로그, 잘못된 건수·수치, 중복·불일치 라벨, 오래된 마지막 샘플,
  다른 데이터소스·쿼리·단위·조회 구간으로는 해당 주장을 만들지 않습니다.
- 검증 관측 없이 가설을 만들거나 선택한 관측 밖의 근거를 인용하면 거부합니다.
- 실패 응답을 보존한 뒤 한 번 수정하는 경로와 보고서의 관측·가설 분리를 확인했습니다.

## 저장된 실제 요약으로 새 모델 실행

이전에 Grafana에서 수집한 동일한 실제 요약을 재사용했습니다. 현재·직전 구간의
외부 API 요청률은 모두 0이고, 현재 구간 Loki 조회는 `no_data`였습니다.
Grafana 재조회나 전체 Agent 루프 실행은 아닙니다. 모델은 실제 로컬 Ollama
`qwen2.5:3b`를 다시 호출했으며 mock 응답을 사용하지 않았습니다.

| 항목 | 결과 |
|---|---|
| 모델 호출 | 1회, 수정 호출 없음 |
| 입력 / 출력 토큰 | 3,183 / 160 |
| 제공된 검증 관측 | 빈 목록 |
| 선택한 관측 / 가설 | `claim_ids: []` / `hypotheses: []` |
| 행동 | `warning_logs` 선택, 실제 도구 실행은 하지 않음 |
| 검증 | `valid: true`, `code: ok` |
| 이전 v3 응답 재검증 | 지표 ID로 경고 존재를 주장한 응답을 `unsupported_hypothesis`로 거부 |

[Langfuse 실행 기록](https://jp.cloud.langfuse.com/project/cmuig2n6v0020ad0cneh2sc10/traces/b06a901f0747fd2cd34a913c895c8c45)에
새 프롬프트·응답·검증 결과를 기록했습니다. 서버에서 부모 span과 generation의 종료·연결,
검증 및 정책 버전 metadata를 확인했습니다. `auto_agent_claim_policy_validity=true`,
`codex_free_text_quality_review=false` 점수의 서버 반영도 확인했습니다.
원본 로그 본문·비밀키·로컬 경로는 제외했습니다.

## 남은 한계

Codex 자체 검토이며 독립적인 사람의 평가는 아닙니다. 이전의 근거 없는 가설은 이번
한 입력에서 재현되지 않았지만 일반적인 조사 품질 향상을 입증하는 결과는 아닙니다.

- `rationale`가 160자 제한 끝에서 문장 중간에 끝났습니다. 모델 응답은 `done_reason: stop`으로
  종료해 출력 토큰 잘림 오류와는 다릅니다.
- `next_checks`의 전체 로그 범위 확인은 현재 최대 100건 조회로 보장할 수 없습니다.
- 검증 관측이 존재해도 자유 문장 원인 가설은 여전히 잘못될 수 있습니다. `semantic_review`는
  `pending`으로 유지합니다. 두 관측 종류 외에 근거 있는 가설도 보수적으로 제외될 수 있습니다.
- 양성 관측의 모델 선택은 합성 단위 테스트만 확인했습니다. 다양한 실제 입력·반복 실행,
  새 Grafana 수집부터 최종 보고서까지의 전체 루프 평가는 남아 있습니다.
