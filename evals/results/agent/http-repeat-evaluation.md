# HTTP 모델 반복 평가

실행일: 2026-09-28 (Asia/Seoul).
실행 ID: `b9b404d685f84738b1b1afa587e739f6`.

## 결과

총 16회 실행 완료. 필요한 직전 조회는 3B **0/6**, 14B **6/6**이었다.
그러나 최종 가설의 예상 상태와 양쪽 구간 근거 인용 검사는 두 모델 모두 **0/6**이었다.
14B의 조회 선택 개선이 조사 완료 품질 향상으로 이어졌다고 결론낼 수 없다.

|---|---:|---:|
| 비교 사례 수 (3종 × 2회) | 6 | 6 |
| 필요한 직전 구간 조회 | 0/6 | 6/6 |
| 최종 가설 상태·양쪽 인용 검사 | 0/6 | 0/6 |
| 잘못된 선택으로 종료 | 4 | 4 |
| 필수 비교 없이 모델이 종료 | 2 | 0 |
| 도구 예산 소진 | 0 | 2 |
| 시간 초과 | 0 | 0 |
| 비교 사례 실행 시간 중앙값 | 38.25초 | 243.82초 |
| LLM 호출 합계 | 19 | 28 |
| 수신 입력 / 출력 토큰 | 49,109 / 5,533 | 76,498 / 5,052 |

각 모델의 빈 데이터 사례 2회는 모두 LLM 호출 없이 종료됐으며 위 비교 성공률에서 제외했다.
토큰 사용량 미수신 호출은 0회였다. 실행 시간에는 실패한 조사도 포함하고, 모델별 실제 조회·호출
횟수가 다르므로 이 표를 순수 추론 속도 벤치마크로 해석하지 않는다.
평가 CLI 종료 코드 1은 자동 품질 검사의 실패이며, 실행 누락이나 테스트 실패가 아니다.

원문 검토에서 확인한 내용:

- **3B:** 두 반복 모두 직전 구간 없이 증가·감소를 주장했다. 두 번째 요청률 사례에서는
  같은 근거로 “감소했다”와 “감소하지 않았다”를 모두 `supported`로 남겼다.
- **14B:** 직전 → 앞 절반 → 뒤 절반 조회를 이어간 뒤 같은 조회를 다시 고르거나 다른 대상을
  추가 조회하다 종료됐다. 보고서에 반영된 가설은 초기 근거만 인용했다. 단, 첫 반복 지연 증가
  사례의 검증 실패 응답에서는 직전 근거를 추가 인용했다. 이 응답은 이미 실행한 조회를 선택해
  거부됐으므로 최종 가설에 반영되지 않았다.
- **반박 사례:** 두 반복의 14B 모두 800ms → 800ms 근거를 얻은 뒤에도 증가 가설을 유지했다.
  새 근거가 있는 상태에서도 판단을 갱신하지 못한 사례다.

14B 호출별 경과 시간은 약 30.37~75.06초였다. 수신한 서버 시간 합계는 로딩 약 0.18초,
입력 평가 643.60초, 출력 생성 873.36초다. 사전 로딩을 제외한 지연 대부분을 로딩 탓으로
설명할 수 없으며, 이번 90초 제한 안에서는 응답을 모두 받았다.

다음 개선 대상은 **새 근거 반영, 이미 조회한 조건에 대한 수정 피드백, 종료 판단**이다.
프롬프트·입력 표현을 한 번에 모두 바꾸거나 모델을 즉시 교체하기보다 한 요소씩 비교해야 한다.

## 실험 설정

이전 45초 제한 비교에서는 14B의 응답을 받지 못해 판단 내용을 비교하기 어려웠다.
이번에는 두 모델에 같은 호출 제한 90초·조사 예산 300초를 적용한다.
기존 네 개발 사례를 모델별 두 번씩 실행하며, 빈 데이터 두 번을 제외하면 모델별 비교 대상은 6회다.

```bash
uv run python -m ops_agent.cli.evaluate_http_agent --planner llm \
  --models qwen2.5:3b huihui_ai/qwen2.5-abliterate:14b-instruct \
  --repeat 2 --seconds 300 --llm-seconds 90 --warmup
```

첫 반복은 3B → 14B, 두 번째는 14B → 3B 순서다. 모델별 배치 전에 빈 메시지로 로딩하며
그 시간은 조사 예산과 별도로 저장한다. 프롬프트·후보·관측값·temperature 0·num_ctx 16,384·
num_predict 1,024·도구 6회·모델 8회·수정 재시도 1회는 유지했다.
기본 운영 설정 45초·180초를 바꾸거나 기본 모델을 교체하지 않았다.

모델은 `qwen2.5:3b`와 `huihui_ai/qwen2.5-abliterate:14b-instruct`다. 14B는 수정 모델이며
파라미터 수만 다른 통제 실험이 아니다. 근거 UUID는 실행마다 달라지고 로컬 실행 부하를 완전히
통제하지 않았다. 두 번의 반복과 작은 개발 데이터셋으로 일반 정확도·속도 우열을 주장하지 않는다.
검토자는 Codex이며 독립·블라인드 평가가 아니다.

## 구현·검증

- `--models`, `--repeat`, `--case`, `--seconds`, `--llm-seconds`, `--warmup`을 평가 CLI에서 지원한다.
- 조사 CLI에서도 `--llm-seconds`를 저장한다. 재개 시 변경하지 않으며 기존 상태의 누락값은 45초다.
- receipt에 적용한 제한·실제 경과 시간을 기록하고, 수신한 서버 로딩·입력 평가·생성 시간을 분리한다.
- 시간 초과, 잘못된 선택, 비교 누락, 가설 상태·인용 실패를 구분한다. `automatic_checks_passed`도 의미 정확성 판정은 아니다.
- 토큰 사용량을 받지 못하면 미상 호출 수를 남긴다. 수신 토큰의 합계와 실제 전체 소비량을 구분한다.
- 사례마다 요약을 저장하므로 중단 시 완료된 결과가 보존된다. 전체 평가 완료 여부는 `status`로 확인한다.

테스트 362개 통과, `ruff check .` 및 `ruff format --check .` 통과.
새 검사는 모델 순서 교대, 규칙 기준선 중복 방지, 중단 시 부분 결과 보존,
잘못된 설정 거부, 미수신 토큰과 시간 초과 분류, 호출별 제한과 남은 예산 적용을 포함한다.

## 근거 위치

`artifacts/evaluations/http-agent/<실행 ID>/` 아래에 다음 파일을 저장한다.

- `metadata.json`: 실험 설정, 데이터셋, 프롬프트·실행 코드 해시.
- `summary.json`: 개별 결과·반복 번호·모델별 집계·실행 시간·사용량.
- `warmup-*.json`: 설치 모델 메타데이터와 사전 로딩 결과.
- 조사별 디렉터리: 조회 원본·모델 응답·SQLite·최종 보고서.
- `manual-review-criteria.json`: 원문 검토 기준. 자동 검사와 의미 검토를 구분한다.
- `manual-review.json`: 사례별 원문 검토. 자동 결과의 `semantic_review`와 별도로 보존한다.

## 6단계에서 남은 범위

이번 작업은 모델 비교를 재현하고 실패 원인을 분리하는 부분이다. 6단계 전체 완료를 뜻하지 않는다.
기존 계획의 장애 재현 범위 확장, 정상·저트래픽·관측 누락 사례 보강, 개발/최종 평가 사례 분리,
동일 조건의 고정 수집+LLM 대 ReAct 비교, HTTP 평가의 Langfuse datasets/experiments 연결은 별도로 남아 있다.
모델의 조회·가설 실패를 개선할 때는 이번 실행을 기준선으로 보존하고, 수정에 사용하지 않은 사례로 재검증한다.
