4/6으로 증가했지만, **이는 보고서 내용 정확도 66.7%를 뜻하지 않는다.**

## v2에서 직접 읽고 확인한 내용 문제

- zero_rate: info 로그만 있는데 needs_investigation으로 분류했고 로그 1건이라는 수치를 누락했다.
- no_data: 분류는 insufficient_evidence로 맞췄지만 facts에 지표가 0으로 반환됐다고 잘못 썼다. 데이터 없음과 유효한 0을 혼동했다.
- warning_present: 경고 1건과 분류는 맞췄지만 샘플 3개를 5분간 요청 3건으로 잘못 설명했다.
- truncated_logs: 초당 요청률 2와 반환 로그 100건, warn 30·info 70건은 정확했다. 그러나 한계 설명에서 지표가 제공되지 않았다는 문장을 반복하고 실제 로그 잘림 설명은 빠뜨렸다.
- invalid_samples: 유효하지 않은 값을 요청률 0으로 바꾸어 썼고 분류도 기대값과 달랐다.
- fractional_rate_errors: error 로그 2건과 분류는 맞췄다. 요청률은 0.25만 서술해 관측 범위 0.25~0.5를 충분히 전달하지 못했다.

이 메모는 Codex의 내용 검토이며 독립적인 사람 평가가 아니다. 자동 산출물의
`semantic_review`는 pending으로 유지한다. 추가 두 사례까지 실행한 뒤 프롬프트를
다시 튜닝하지 않았으며, 이 작은 사례 집합으로 일반 성능을 주장하지 않는다.

## 해석과 다음 작업

분류 정책과 단위 설명을 명시하면 일부 분류는 개선되지만, 작은 모델이 관측 사실을
정확히 서술하도록 보장하지는 못했다. 특히 no_data를 0으로 바꾸는 오류는 분류 점수만
측정하면 놓친다. 다음에는 Langfuse에 버전별 응답과 개별 자동 검사 결과를 연결하고,
내용 검토 결과를 별도로 기록할 수 있도록 하자. 14B의 v2 결과는 이번 실행에서
측정하지 않았으므로 이전 v1 결과와 직접적인 개선 비교를 주장하지 않는다.
